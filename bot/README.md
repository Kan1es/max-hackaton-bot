# MAX-бот «Навигатор мер поддержки»

Диалоговый бот на [`maxapi`](https://github.com/max-messenger/max-botapi-python) (MAX-team-verified форк). Собирает профиль за 4 шага (статус → регион → сфера → приоритет), после каждого шага синхронизирует его с backend, затем показывает подобранные программы карточками с кнопкой «Сохранить» и предлагает сравнить их в mini app.

## Получение токена

1. Напишите `@MasterBot` в MAX, создайте бота — получите токен.
2. Документация API: https://dev.max.ru/docs-api

## Локальный запуск (без Docker)

```bash
cd max-hackaton
cp .env.example .env
# MAX_BOT_TOKEN — токен бота
# SERVICE_TOKEN — общий с backend секрет, иначе API не пустит бота
#   (либо поднимите backend с REQUIRE_SIGNED_INIT_DATA=False)

pip install -r bot/requirements.txt
python -m bot.main
```

Backend должен быть уже запущен: бот загружает варианты ответов из `GET /api/v1/options/` при старте и без него не поднимется (лучше упасть, чем рисовать клавиатуры по устаревшим константам). Загрузка делает до 10 попыток с паузой, так что порядок запуска не критичен.

По умолчанию бот работает через long polling (`USE_WEBHOOK=False`); `bot.delete_webhook()` вызывается автоматически.

## Запуск через Docker Compose

```bash
docker compose up --build
```

Бот стартует только после того, как backend пройдёт healthcheck, и ходит на `http://web:8000/api/v1`.

## Как бот общается с API

Бот — серверный сервис и не может подписать браузерный `initData`, поэтому представляется парой заголовков:

```
X-Service-Token: <SERVICE_TOKEN>
X-Max-User-Id:   <id пользователя MAX>
```

Профиль и заявки backend определяет по этим заголовкам. Идентификаторы профиля в боте не хранятся вообще — поэтому кнопка «Сохранить» работает и после рестарта бота, когда память состояний уже очищена.

## ИИ-консультант

После подбора (и вообще в любой момент) пользователь может просто написать вопрос — «какие документы нужны для первой программы?», «чем субсидия отличается от гранта?». Бот:

1. включает индикатор «печатает…» и держит его, пока модель отвечает;
2. отправляет вопрос и последние 3 обмена репликами в `POST /api/v1/assistant/ask` — backend добавляет профиль и каталог;
3. присылает ответ с кнопками «📋 <программа>» на программы, на которые опирается ответ; кнопка открывает полную карточку с «⭐ Сохранить».

Вопрос посреди анкеты тоже получает ответ, а следом — напоминание вернуться к кнопкам. Текстовые шаги анкеты (свой регион, описание сферы) обрабатываются раньше и в консультант не уходят.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | Пройти опрос заново и получить подбор |
| `/my` | Сохранённые программы со статусом и прогрессом по документам |
| `/help` | Справка и примеры вопросов |

Список команд задаётся в @MasterBot (MAX не принимает его через API).

## Структура

| Файл | Назначение |
|---|---|
| `main.py` | Точка входа: проверка конфигурации, загрузка опций, polling/webhook |
| `dialog.py` | Хендлеры диалога (FSM по шагам профиля) + выдача карточек программ |
| `states.py` | Состояния FSM (`ProfileForm`) |
| `keyboards.py` | Инлайн-клавиатуры, собранные из загруженных с backend опций |
| `options.py` | Кэш опций диалога (источник — `app/core/options.py` через API) |
| `api_client.py` | HTTP-клиент: аутентификация, ретраи, понятные ошибки |
| `config.py` | Настройки из `.env` (`pydantic-settings`) |

## Обработка ошибок

Любой сбой backend превращается в `BackendError` и пользователь видит внятное сообщение вместо молчания. Логи ошибок содержат метод, путь, статус и начало тела ответа.

## Известные ограничения MVP

- **ИИ на бесплатной модели** — при перегрузке OpenRouter консультант отвечает поиском по каталогу, а классификатор сферы — по ключевым словам. Порог `CLASSIFY_CONFIDENCE_THRESHOLD` (0.6): уверенный ответ его проходит, неуверенный — возвращает пользователя к кнопкам.
- **Кнопка «Сравнить в приложении»** использует `OpenAppButton` — mini app должен быть зарегистрирован в настройках бота на dev.max.ru. Если имя бота не удалось определить, бот отправит ссылку `MINIAPP_URL` текстом.
- **Состояние диалога** (`MemoryContext`) хранится в памяти процесса: рестарт сбрасывает незавершённый шаг. Уже отвеченные шаги лежат в Postgres и не теряются. Для прод-нагрузки стоит вынести состояние в Redis.
