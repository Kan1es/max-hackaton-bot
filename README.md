# Max Hackathon — «Навигатор мер поддержки»

Бот и mini app для MAX, которые помогают самозанятым и ИП находить гранты, льготные займы, субсидии и налоговые льготы.

**Назначение.** Самозанятый или начинающий ИП не знает, какие из сотен федеральных и региональных мер поддержки подходят именно ему. Условия разбросаны по МСП.РФ, сайтам Корпорации МСП и региональных фондов, а зависят они от статуса, региона и сферы. Навигатор за четыре вопроса в чате собирает профиль и возвращает короткий список подходящих программ: у каждой есть объяснение «почему подходит» и чек-лист документов, а прогресс подготовки можно отслеживать.

| Для проверки | |
|---|---|
| Бот в MAX | https://max.ru/t814_hakaton_max_bot |
| Mini app | https://maxnalog.ru:8444 (открывается кнопкой из бота; в браузере — гостевой режим, только каталог) |
| API | `https://maxnalog.ru:8444/api/v1` — контракт в [`openapi.json`](openapi.json), обязательные проверки в [`DATA-API.yaml`](DATA-API.yaml) |
| Тестовые данные | [`app/db/seed_data/support_programs.json`](app/db/seed_data/support_programs.json) |

## 🧭 Основной пользовательский сценарий

1. Пользователь открывает бота в MAX и нажимает «Начать» (или отправляет `/start`).
2. Бот задаёт 4 вопроса кнопками: **статус** (самозанятый / регистрирую ИП / ИП) → **регион** (или «Другой регион» и ввод текстом) → **сфера** (кнопкой или своими словами — её определит LLM) → **приоритет** (деньги на старт, льготный займ, обучение…). Каждый ответ сразу сохраняется в профиль на backend.
3. Бот присылает до трёх подходящих программ: сумма, срок, «подходит по региону / сфере / приоритету» и кнопка «⭐ Сохранить».
4. Кнопка «Открыть приложение» запускает mini app: полный ранжированный список, каталог с поиском и фильтром, карточка программы и «Мои программы» с чек-листом документов и статусом заявки.
5. В любой момент можно написать боту вопрос своими словами. ИИ-консультант отвечает по каталогу с учётом профиля и даёт кнопки на программы, на которые опирается ответ.

Результат: пользователь за 1–2 минуты получает персональный список мер с объяснением, почему они подходят, и знает, какие документы собрать.

## 🏗 Состав и архитектура

```text
 Пользователь MAX
   │ чат                        │ mini app (WebView, HTTPS)
   ▼                            ▼
 ┌──────────┐  X-Service-Token  ┌──────────────┐  Authorization: tma <initData>
 │   bot    │ ────────────────▶ │   miniapp    │ ──┐  (nginx: статика + /api прокси)
 │ (maxapi) │                   └──────────────┘   │
 └────┬─────┘                                      ▼
      │  HTTP /api/v1          ┌──────────────────────────────┐
      └──────────────────────▶ │  web — FastAPI               │ ──▶ OpenRouter (LLM)
                               │  подбор, профиль, заявки, ИИ │
                               └──────────────┬───────────────┘
                                              ▼
                                       ┌─────────────┐        ┌───────────────────┐
                                       │ db Postgres │ ◀───── │ collector (прод)  │ ──▶ МСП.РФ, Корпорация МСП
                                       └─────────────┘        └───────────────────┘
```

| Сервис (compose) | Что делает | Где код |
|---|---|---|
| **web** | FastAPI + PostgreSQL: каталог программ, профили, подбор, «Мои заявки», ИИ-консультант | `app/` |
| **bot** | Диалог сбора профиля в MAX, выдача подобранных программ, консультант | [`bot/`](bot/README.md) |
| **miniapp** | React/Vite интерфейс: рекомендации, каталог, чек-листы документов; nginx | [`miniapp/`](miniapp/README.md) |
| **db** | PostgreSQL 16 | — |
| **collector** | Только в прод-конфигурации: раз в сутки собирает реальные меры с госпорталов | `app/collector/` |

Бот и mini app **не содержат собственной копии данных или логики**: каталог программ, варианты ответов и правила подбора живут только на бэкенде и раздаются по HTTP. Профиль, сохранённые программы и отметки документов лежат в Postgres, поэтому чат и приложение всегда показывают одно и то же.

## 🚀 Запуск одной командой

Нужны только Docker и Docker Compose v2.

```bash
cp .env.example .env
# впишите MAX_BOT_TOKEN (выдан организаторами / @MasterBot в MAX) и SERVICE_TOKEN:
#   python3 -c "import secrets; print(secrets.token_urlsafe(32))"

docker compose up --build
```

Сборка с нуля занимает меньше минуты (замер `docker compose build --no-cache`: 48 с без учёта скачивания базовых образов). Миграции применяются автоматически, тестовый каталог загружается при старте backend.

| Адрес | Что это |
|---|---|
| http://localhost:8080 | Mini app (nginx, проксирует `/api` на backend) |
| http://localhost:8000/docs | Swagger backend |
| http://localhost:8000/health | Health check |
| — | Бот (long polling, без публичного порта) |

`docker-compose.yml` описывает прод-конфигурацию; `docker-compose.override.yml` подхватывается автоматически и добавляет локальные удобства — hot reload, проброс порта Postgres и `REQUIRE_SIGNED_INIT_DATA=False`, чтобы Swagger и curl работали без подписи. **При деплое этот файл нужно убрать.**

> Без `MAX_BOT_TOKEN` контейнер `bot` не стартует, остальной стек (API и mini app в браузере) работает. Не запускайте бота локально с тем же токеном, что и на сервере: long polling делит события между процессами, и часть сообщений уйдёт не туда.

### Остановка и повторный запуск

```bash
docker compose stop            # остановить, контейнеры и данные остаются
docker compose start           # запустить снова
docker compose down            # удалить контейнеры; данные Postgres сохраняются в томе postgres_data
docker compose up --build      # повторный запуск (после изменений — пересборка)
docker compose down -v         # полный сброс вместе с базой; при следующем старте каталог загрузится заново
docker compose logs -f web bot # логи
```

## 📱 Возможности MAX

| Возможность | Где | Зачем пользователю |
|---|---|---|
| **Чат-бот + mini app как один продукт** | Кнопка «Открыть приложение» в боте | Короткий диалог — в чате, сравнение и чек-листы — в приложении; данные общие |

| **`shareMaxContent`** — «Поделиться» | Карточка программы | Предприниматель пересылает программу в чат MAX бухгалтеру, партнёру или в бизнес-сообщество. Получатель видит условия и ссылку на бота и сразу проходит тот же сценарий. Если метода нет — системный `shareContent`, в браузере — Web Share API или буфер обмена |
| **`BackButton`** | Карточка, чек-лист, документ | Системная кнопка «Назад» в шапке MAX вместо поиска стрелки на странице |
| **`HapticFeedback`** | Сохранение программы, отметка документа, ошибки | Тактильное подтверждение, что действие записано на сервере, и отдельный сигнал при ошибке |
| **`openLink`** | «Открыть источник» | Официальный портал открывается во внешнем браузере, mini app не теряет состояние |
| **Индикатор «печатает…»** | ИИ-консультант в боте | Пользователь видит, что ответ готовится (модель отвечает до 25 с) |

Код — [`miniapp/src/bridge.js`](miniapp/src/bridge.js); все вызовы безопасно деградируют вне MAX и в старых клиентах. Тесты — `miniapp/src/__tests__/bridge.test.js`.

## 🗂 Работа с тестовыми данными

- **Что это.** [`app/db/seed_data/support_programs.json`](app/db/seed_data/support_programs.json) — 19 программ поддержки, подготовленных вручную по открытым описаниям. Все помечены `is_mock=true` и в интерфейсе подписаны «тестовые данные».
- **Как попадают в базу.** Автоматически при каждом старте backend (`app/db/seed.py`): строки сопоставляются по названию и обновляются на месте, дублей нет. Реальные программы сборщика этот процесс не трогает.
- **Когда видны.** Пока активных реальных программ меньше `DEMO_CATALOG_MIN_REAL` (50). В локальном стеке сборщика нет, поэтому каталог состоит только из тестовых программ, и подбор воспроизводим.
- **Как изменить.** Отредактируйте JSON и перезапустите backend: `docker compose restart web`.
- **Как сбросить.** `docker compose down -v && docker compose up --build` — база создаётся заново с тестовым каталогом, профили и заявки удаляются.
- **Тестовые пользователи.** Отдельных учётных записей нет: пользователь — это ID в MAX. Для проверки API используйте любые ID. В `DATA-API.yaml` зарезервированы `900000001` и `900000002` (второй — для проверки изоляции данных).

### Локально через API (без MAX)

После `docker compose up --build` (override-файл разрешает `X-Max-User-Id` без подписи):

```bash
curl -s localhost:8000/health
# {"status":"ok","database":"connected","version":"0.1.0"}

curl -s -X POST localhost:8000/api/v1/profile/ -H 'X-Max-User-Id: 42' -H 'Content-Type: application/json' \
  -d '{"status":"Самозанятый","region":"Краснодарский край","industry":"Услуги","priority":"Деньги на старт"}'
# профиль с заполненными полями

curl -s 'localhost:8000/api/v1/programs/match/me?limit=3' -H 'X-Max-User-Id: 42'
# до трёх программ с "score" и "reasons": ["доступна в вашем регионе", "подходит по сфере", ...]

curl -s -X POST localhost:8000/api/v1/applications/ -H 'X-Max-User-Id: 42' -H 'Content-Type: application/json' -d '{"program_id":1}'
# {"status":"saved","checked_docs":[],"program":{...}}

curl -s -o /dev/null -w '%{http_code}\n' localhost:8000/api/v1/profile/me
# 401 — без аутентификации данные пользователя недоступны
```

Mini app в браузере (http://localhost:8080) открывается в гостевом режиме: каталог доступен, персональные разделы — только внутри MAX, где есть подписанный `initData`.

### Автоматическая проверка API

[`DATA-API.yaml`](DATA-API.yaml) описывает 17 обязательных проверок: роли, заголовки, тела запросов, ожидаемые коды и поля ответа. Против прода они выполняются с `X-Service-Token` (значение — на первом слайде презентации). Тот же набор прогоняется в CI на каждом коммите (`tests/test_contract.py`): дважды подряд, с прод-настройками аутентификации и на реальном тестовом каталоге. Этот же тест проверяет, что `openapi.json` совпадает с кодом.

### Деплой на VPS (maxnalog.ru)

1. В панели REG.RU → «DNS-серверы и управление зоной» задайте A-записи `@` и `www` = IP сервера (вместо адреса виртуального хостинга).
2. Положите продакшен-окружение в `deploy/.env.production` (в git не попадает): `DOMAIN=maxnalog.ru`, `MINIAPP_URL=https://maxnalog.ru`, `HTTPS_PORT` (если 443 на сервере занят — например, `8444`, тогда адрес `https://maxnalog.ru:8444`), стойкий `POSTGRES_PASSWORD`, `REQUIRE_SIGNED_INIT_DATA=True`.
3. Запустите с локальной машины:

```bash
./deploy/deploy.sh root@<IP сервера>
```

Скрипт ставит Docker (если его нет), копирует проект и поднимает `docker-compose.yml` + [`docker-compose.prod.yml`](docker-compose.prod.yml): наружу открыт только Caddy на 80 и `HTTPS_PORT` (443 по умолчанию), он сам выпускает и продлевает сертификат Let's Encrypt. `.env` на сервере создаётся один раз и при следующих деплоях не перезаписывается.

4. В настройках бота на dev.max.ru укажите адрес mini app — `https://maxnalog.ru` (или с портом, если `HTTPS_PORT` не 443).

> Бот работает через long polling: не запускайте его одновременно локально и на сервере — события будут делиться между процессами.

## 🔐 Аутентификация

Профильные эндпоинты **не принимают идентификатор пользователя в теле или пути** — он берётся из аутентификации. Иначе любой мог бы прочитать чужие заявки, подставив соседний `profile_id`.

| Кто | Как представляется | Проверка |
|---|---|---|
| Mini app | `Authorization: tma <WebApp.initData>` | HMAC-SHA256 подпись на `MAX_BOT_TOKEN` + срок жизни |
| Бот | `X-Service-Token` + `X-Max-User-Id` | Сравнение с общим секретом `SERVICE_TOKEN` |
| Swagger/curl | `X-Max-User-Id` | Только при `REQUIRE_SIGNED_INIT_DATA=False` |

`initDataUnsafe` в mini app используется **только** для отображения имени и никогда — как идентификатор.

## 🧮 Подбор программ

Единственная реализация — [`app/services/matching.py`](app/services/matching.py). Работает так:

1. **Жёсткий фильтр.** Отсеиваются программы другого региона и те, под чей статус заявитель заведомо не подходит (например, самозанятый и программа только для реестра МСП).
2. **Причины.** Для каждой оставшейся программы собираются совпадения: регион (25), сфера (30), приоритет (25), статус (20).
3. **Порог.** Программа показывается, если совпало **минимум две** причины.
4. **Сортировка** по сумме весов, ничьи разрешаются по `id`, чтобы порядок не прыгал между запросами.

Причины возвращаются клиенту текстом («подходит по сфере»), поэтому и бот, и mini app объясняют, почему программа предложена.

> Это предварительный подбор. Возраст, доход, наличие в реестре МСП, задолженности и прочие условия участия не проверяются — это не решение о праве на поддержку.

## 🤖 ИИ-слой (OpenRouter)

LLM подключена через [OpenRouter](https://openrouter.ai) — основная модель `qwen/qwen3.8-27b:free`, запасные перечислены через запятую в `OPENROUTER_MODEL` (OpenRouter сам переключается на следующую). Общий клиент — [`app/services/openrouter.py`](app/services/openrouter.py).

| Функция | Где | Что делает |
|---|---|---|
| Классификация сферы | `POST /classify/`, [`llm_classifier.py`](app/services/llm_classifier.py) | Пользователь описывает бизнес своими словами — модель выбирает одну из отраслей |
| ИИ-консультант | `POST /assistant/ask`, [`assistant.py`](app/services/assistant.py) | Отвечает на любые вопросы о мерах поддержки. Весь каталог и профиль передаются в промпт, модели запрещено выдумывать программы; программы, на которые опирается ответ, возвращаются id и превращаются в кнопки в боте |

Особенности:

- **Reasoning выключен** (`"reasoning": {"enabled": false}`): Qwen3 по умолчанию «думает», тратит на это ~250 токенов из `max_tokens` и втрое дольше отвечает — короткий бюджет классификатора возвращал пустой ответ.
- **Ретраи 429.** У `:free` моделей общий лимит, 429 приходят и уходят за секунды — клиент повторяет запрос с нарастающей паузой, пока укладывается в таймаут (`OPENROUTER_TIMEOUT` для классификатора, `ASSISTANT_TIMEOUT` для консультанта).
- **Деградация без ошибок.** Нет ключа, лимит, таймаут — `/classify` переходит на ключевые слова, консультант — на поиск по каталогу. Такие ответы помечены `is_stub: true`.
- **Чистка ответа.** Markdown, внутренние номера `[3]` и случайные иероглифы (Qwen иногда переходит на китайский) вырезаются.

Для стабильной работы на демо лучше платный ключ или модель без `:free` — бесплатный пул часто перегружен.

## 🗄 Модели данных

| Таблица | Назначение |
|---|---|
| `users` | Пользователь MAX (`max_user_id`) |
| `profiles` | Профиль из диалога: статус, регион, сфера, приоритет (1-к-1 с `users`) |
| `support_programs` | Каталог мер поддержки |
| `matches` | Текущий top-3 подбора на профиль, для аналитики (upsert, без дублей) |
| `applications` | «Мои заявки»: статус + отметки документов (`checked_docs`) |

Каталог наполняет [сборщик с госпорталов](#-реальные-программы-с-госпорталов). Тестовый снапшот из 19 программ ([`app/db/seed_data/support_programs.json`](app/db/seed_data/support_programs.json), `is_mock=True`) остаётся запасным: он показывается рядом с реальными программами (с пометкой «тестовые данные»), пока активных реальных меньше `DEMO_CATALOG_MIN_REAL` (50), и скрывается, когда каталог наполнится.

## 🏛 Реальные программы с госпорталов

[`app/collector`](app/collector) — контейнер `collector`, раз в сутки (`python -m app.collector --loop`).

| Источник | Что даёт | Как |
|---|---|---|
| `msp_rf` — Цифровая платформа МСП.РФ | Федеральные, региональные и муниципальные меры, включая все отборы Минфина с promote.budget.gov.ru; фильтр по региону и типу заявителя | Bitrix AJAX `nota:regions.support.proactive → getItems` + публичная страница меры. **Только с российского IP** |
| `corpmsp` — Корпорация МСП | Федеральные программы: льготные кредиты, лизинг, гарантии, гранты молодым предпринимателям | HTML раздела «для бизнеса» |

Как устроено:

1. Адаптер отдаёт текст меры; структурированные поля из API (название, срок приёма заявок, федеральная/региональная) берутся как есть.
2. LLM превращает текст в поля каталога — вид поддержки, сумма, условия, кто может получить, документы — и решает, подходит ли мера малому бизнесу.
3. Строки ключуются по `(source, external_id)`. Неизменившийся текст повторно в LLM не отправляется (хэш включает версию промпта). Закрытые отборы и пропавшие из источника меры скрываются (`is_active=False`), но не удаляются. Если проход не завершился — ничего не скрывается.

**Российский IP.** МСП.РФ блокирует иностранные адреса. Контейнер `ru-tunnel` (профиль `ru-tunnel`) держит SSH-туннель на российский VPS и отдаёт SOCKS5-прокси `socks5://ru-tunnel:1080` — на самом VPS ничего ставить не нужно, достаточно входа по ключу `deploy/ru_tunnel_key`. К OpenRouter сборщик ходит напрямую.

**Лимиты LLM.** Без баланса OpenRouter даёт 50 бесплатных запросов в сутки на аккаунт — и бот, и сборщик тратят их. Сборщик берёт не больше `COLLECTOR_LLM_BUDGET` (30) за проход, а при исчерпании суточной квоты останавливается и продолжает после сброса. С балансом от $10 лимит — 1000 в сутки; тогда поднимите бюджет, и полный каталог соберётся за один проход.

```bash
python -m app.collector --source msp_rf --limit 5 --dry-run   # посмотреть, что извлекается, без записи
```

## ⚠️ Известные ограничения

**Откуда данные — и что из них модельное.**

| Данные | Происхождение | Как отличить |
|---|---|---|
| Реальные меры поддержки | Собраны с МСП.РФ и сайта Корпорации МСП; название, сроки и уровень (федеральная/региональная) — как в источнике | `is_mock=false`, заполнены `source` и `source_url`, в интерфейсе ссылка на первоисточник |
| Поля реальных мер: вид, сумма, условия, документы | Извлечены LLM из текста страницы меры | Могут содержать неточности — перед подачей сверяйтесь с источником по ссылке |
| Тестовый каталог (19 программ) | Подготовлен вручную по открытым описаниям программ | `is_mock=true`, подпись «тестовые данные»; скрывается, когда реальных мер ≥ 50 |
| Причины совпадения и порядок | Рассчитываются нашими правилами подбора | Это рекомендация, а не решение о праве на поддержку |
| Ответы ИИ-консультанта | LLM по нашему каталогу и профилю | Модели запрещено называть программы вне каталога, а кнопки строятся только по id из каталога; при недоступности LLM — поиск по каталогу, `is_stub=true` |

**Функциональные ограничения MVP.**

- **Подбор предварительный.** Возраст, доход, наличие в реестре МСП, задолженности и прочие условия участия не проверяются.
- **Регионы.** Сборщик опрашивает МСП.РФ по четырём регионам анкеты (`COLLECTOR_MSP_REGIONS`); для остальных регионов показываются федеральные меры.
- **Каталог наполняется постепенно**, пока у OpenRouter нет баланса: не больше 30 новых мер в сутки.
- **ИИ на бесплатном тарифе.** `:free` модели OpenRouter часто отвечают 429 — тогда бот честно переходит на поиск по каталогу. Для прода нужен платный ключ.
- **Интеграции только на чтение.** Подать заявку из навигатора нельзя: «Мои заявки» — личный трекер подготовки, а не отправка в ведомство (интеграции с Госуслугами и МСП.РФ на подачу нет).
- **Уведомления.** Переключатели в профиле mini app пока ничего не рассылают.
- **Состояние диалога бота** хранится в памяти процесса: рестарт сбрасывает незавершённый шаг анкеты (уже отвеченные — нет, они в Postgres).
- **Локальный запуск.** Вне MAX mini app работает в гостевом режиме (только каталог): подписанный `initData` бывает только внутри MAX. Сборщик в локальный стек не входит — ему нужен российский IP и ключ LLM.
- **Прод на нестандартном порту** `8444`: порт 443 на сервере занят.
